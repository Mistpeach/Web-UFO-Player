🧪 浏览器能力探测

一页看清当前浏览器与打开方式（file:// 还是 http://）下，哪些功能可用、哪些会降级。

准备探测…
1. 为什么 file:// 和 http:// 下能力不同：
浏览器把 file:// 当作不透明来源（opaque origin）：fetch / XHR 读本地文件会被直接拦下， 剪贴板 API（navigator.clipboard）在多数宿主里也干脆不暴露或调用即拒绝；showDirectoryPicker 等 File System Access 接口同样要求安全上下文。http://127.0.0.1 与 https:// 属于安全上下文， 这些能力才会正常开放。所以「双击打开」能用和不能用，本质是打开方式决定的，不是浏览器坏了。

2. 文件夹批量导入 / 写出依赖 showDirectoryPicker：
手机上（Android Chrome / iOS Safari）没有这个接口，无法整目录读写，需要降级成 <input type="file" multiple> 的多选文件（必要时加 webkitdirectory 递归选目录），或者逐个文件拖拽导入。

3. 如果蓝牙或文件夹功能不可用：
在本仓库根目录起一个本地静态服务器，再用 http://127.0.0.1 打开本页即可：
python -m http.server 8000
然后访问 http://127.0.0.1:8000/TestPage/capability-check.html
