🔗 资源引用完整性检查

把仓库根目录（或任意一个目录）整个拖进下面的框里，本页会逐个读入其中的 HTML / CSS， 抽出所有 href / src / url() / @import, 再判断这些本地资源是否真的存在于你拖进来的文件集合里。全程离线、不联网、不上传。

为什么必须「拖文件夹」，而不是自动扫描？
· 浏览器不允许 file:// 页面读取目录（没有目录列表 API）；用 fetch 去读本地文件会被 CORS 拦下。
· 但你手动拖进来的文件夹不一样：DataTransferItem.webkitGetAsEntry() 可以递归拿到每个文件， 再用 File.prototype.text() 读出内容 —— 它在 file:// 下完全可用。
· 所以本页的模型是「用户提供文件集合，页面只做分析」，因此双击本文件直接打开就能用，不需要任何服务器。
这个检查有什么用？
· 最典型的静默事故是「归档快照 / 发布目录漏带了 CSS」：页面照样能打开、按钮也在，只是完全没样式， 肉眼很难第一时间发现。仓库里 WaveControler\history\gen_versions.ps1 有一份针对快照目录的同款检查； 本页是它的仓库级版本，范围是「你拖进来的整棵目录树」。
· 顺带一个自查结论：把当前仓库整棵树拖进来跑一遍，是 79 个 HTML / CSS、113 条本地引用， 结果是零失效 —— 也就是说现在没有这类漏带问题。 相对路径的基准：
· 每个引用都相对于引用所在文件的那个目录解析，不是相对于你拖入的根目录。 例如 WaveControler\RemoteSlave.html 里的 js/link.js 会被解析成 WaveControler/js/link.js，而不是 js/link.js。
判定口径：
· 大小写不敏感（Windows 文件系统本来就不区分大小写）；\ 与 / 等价； 比较前会去掉 ?query 与 #hash、还原 %20 之类的转义。
· 会跳过 http(s): / // / data: / mailto: / javascript: / # 开头 / / 开头的站点绝对路径 / 空串。
· 「文件不存在」严格来说只代表不在你拖进来的集合里 —— 如果你只拖了仓库的一部分，报错里可能混有真·外部依赖。 想得到准确结论就拖整个仓库根目录。
