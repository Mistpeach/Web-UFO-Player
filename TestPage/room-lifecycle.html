这个剧本覆盖了什么
· create → created：房号是 8 位数字，建房者角色固定 slave（被控方）
· join → joined：加入者角色固定 master（主控方）；建房方应收到 peer event:"joined"
· 第三人 join → error room-full：v3.0 修过的致命坑 —— 以前第三人会看到「已进入房间」然后永远卡住， 因为把「WebSocket 握手成功」当成了「已经进了房间」。现在服务器拒绝时只回一条 error 且不关连接， 客户端必须区分 opened 与 joined。
· relay → 对端 relay：payload 必须逐字不变，只额外补 s 与 from
· ping → pong：c 必须原样带回，否则客户端算不出 RTT
· 非法房号 → error bad-room；不存在的房号 → error room-not-found
· leave → 对端收到 peer event:"left"（对被控端是安全关键：收到即立即安全停机）

没覆盖的（需要真实设备和更长时间）
· 房间空闲 10 分钟后的回收（room.idleMs）—— 跑一轮要等十分钟，不适合放这里
· 消息分片（超过 8KB 的业务消息）。协议规定每片都是独立的 relay，服务器不感知分片
· 限流（每 IP 每分钟 10 次建房/加入）—— 本剧本只建房 2 次左右，不会触发
· 业务层语义（state / ack / stop / bye / resume）属于客户端之间的事， 服务器只做透明转发；那部分见 remote-selftest.html 与 sync-trace.html

没有服务器怎么办：RemoteServer/ 目录里有完整部署教程（含 Docker、systemd、nginx/Caddy 反代示例）。 只想本地验证的话，也可以直接用波形控制器里的「本地调试模式」（BroadcastChannel，不需要服务器）。
