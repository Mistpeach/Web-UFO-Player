# 【更新】UFO 助手 波形控制器 v3.0 —— 远程控制正式可用

> 本文可直接用于论坛发帖。本次是波形控制器（🌊）的更新，**脚本播放器（🚀）没有改动**。
> 在线地址见仓库首页；建议用 **Chrome / Edge** 打开（需要 Web Bluetooth）。

---

## 一句话概括

**远程控制从"能连上"变成"真的能用"了。** 之前 wss:// 服务器这条路存在一个致命缺陷，
房间能建、两边能互相看到在线，但业务消息一条都过不去 —— 主控永远"同步中"、控制不了对方。
这一版修好了，并且顺带修了一批同步、恢复、通道独立与示波器的问题。

---

## 🌐 远程控制：核心缺陷修复

v2.0 就带了远程控制的界面，也做了本地调试模式（同一浏览器两个标签页直连），
但**真实服务器（`wss://`）这条路一直没跑通**。原因是一个很隐蔽的分片信封问题：

| # | 问题 | 修复后 |
|---|---|---|
| 1 | **业务消息无法穿过服务器**：中继载荷是分片信封 `{c,i,n,d}`，真正的消息在 `d` 里，但接收侧从没拆过包，每条消息都被判为"没有类型"丢掉。表现就是房间建好了、两端互相显示在线，主控却永远"同步中"、看不到被控信息、也控制不了对方 | 接入分片重组；**超过 8KB 的完整波形也能正确送达** |
| 2 | 被控端看不到「主控↔服务器」延迟、时钟偏差、端到端估算（一直显示 `—`） | 主控在状态里**捎带这两个只有它测得出的值**；端到端 = 本端↔服务器 + 主控↔服务器 |
| 3 | 被控点「解锁」后，主控那边通道复选框**仍然是灰的** | 新增 **resume 报文**（被控 → 主控）：主控无法自行解除急停锁定（这是安全设计），必须由被控告知 |

> 第 1 条是那种"看起来网络问题、实际是解析问题"的坑。服务器日志、`/health`、`peer joined` 全部正常，
> 唯独业务层静默丢包 —— 用一个能同时抓 WebSocket 收发报文的诊断页才定位到。

## 🔄 同步与掉线恢复

| # | 问题 | 修复后 |
|---|---|---|
| 4 | **同步死循环**：主控每收到一次确认就重新推一版新状态，版本号无限空转，同步永远到不了"已同步"，同时以每秒几十条的速率空刷网络 | 只在状态**真的变化**时下发（实测 3 秒内 93 次 → **1 次**） |
| 5 | 主控掉线超过 8 秒再回来，**链路恢复后仍无法控制**，必须重开房间 | 三处根因一起修好（见下） |
| 6 | 主控主动退出 / 关标签页时，被控要**白等约 6.5 秒**才因心跳超时停机 | 主控先发 **bye 报文**告别，被控立即停机 |

第 5 条其实是三个叠加缺陷：

- **被控侧**：失联标记永不清除 → 同一次失联只处理一次，之后再也不响应
- **主控侧**：失联时没把对端标记为离线 → "对端回来了"这件事从未被察觉，因此从不补推状态
- **被控侧**：安全停机后的锁定无法自动放开 → 状态即使送到了也被挡在门外

## 🔒 安全

| # | 问题 | 修复后 |
|---|---|---|
| 7 | **急停依赖蓝牙健康**：`eng.setEnabled`、`ble.send`、`requestStop` 挤在同一个 `try` 里，蓝牙一断 `ble.send` 抛异常，急停信号就发不出去 —— **主控完全收不到急停，仍在正常下发命令** | 拆成各自独立的 `try`；急停不再受蓝牙状态影响 |
| 8 | 「失联停机」与「用户急停」混成一种锁定，界面也说不清 | 明确区分：**用户急停 = 永久锁定，只有被控方能解**；**失联/蓝牙断开 = 临时停机，恢复后自动继续** |

被控端三处失联兜底（自己断 / 主控离开 / 心跳超时）依旧统一走同一个安全停机出口，没有遗漏路径。

## 📈 通道独立与示波器

| # | 问题 | 修复后 |
|---|---|---|
| 9 | **A 通道波形会莫名从头重播**：主控只调了 B 通道参数，A 却在播到一半时被拉回起点 | 逐通道比对，**没变化的通道一律不碰引擎** |
| 10 | 主控端**波形图一片空白** | 卡片里缺 canvas 元素、且从未挂载示波器；已补上画布、挂载与缩放重绘 |
| 11 | 时间扫描线行为不确定 | 明确为：**换波形从新波形开头播**；**取消某通道输出时扫描线停在起始位置**；主控勾选后扫描线正常前进 |

第 9 条的根因值得一提：引擎的 `setEnabled` 是**故意**设计成"每次调用都把时间原点重置到此刻"的
（为了让"连点两次试一下"能重播），但同步侧对 A、B 两路都照调了一遍，于是"改 B 动了 A"。

## 🖥️ 服务器端

服务器程序在仓库 `RemoteServer/` 目录，本次**没有功能变更**（它只做转发、不解析业务载荷）。
目录内包含：

- 服务器程序（零依赖，自带 WebSocket 实现）
- 部署教程：**宝塔面板向 / 命令行向**，另附 Nginx、Caddy、Docker、systemd 配置
- 协议文档与原理说明

> 部署时最容易踩的坑是反向代理漏了 `Upgrade` / `Connection` 头，文档里已重点标注。

## 📌 已知限制

- 只支持 **Chrome / Edge**（Firefox / Safari 不支持 Web Bluetooth）
- **BLE 单连接**：脚本播放器和波形控制器**不能同时控制同一台玩具**
- 有效波形频率上限约 **10Hz**（每 50ms 发一包）
- 数据存在**浏览器本地**：清缓存 / 换浏览器 / 换域名都会丢 —— 请用「导入 / 导出 / 管理」定期备份
- 远程控制需要**自建一台中转服务器**；被控方页面必须保持**前台运行**，否则浏览器降频会影响发包
- 「我↔服务器」延迟在**本地调试模式**下不显示（那个模式不走服务器，是正确的）
- 波形控制器目前是 **v3.0 Beta**
