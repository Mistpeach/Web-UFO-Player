# 【更新】UFO 助手 波形控制器 v3.1 —— 一键分享控制链接

> 本文可直接用于论坛发帖。本次是波形控制器（🌊）的小版本更新，**脚本播放器（🚀）没有改动**。
> 建议用 **Chrome / Edge** 打开（需要 Web Bluetooth）。

---

## 一句话概括

被控方建房后，现在可以**直接复制一条控制链接**发给对方 —— 对方打开就已经填好服务器和房间号，
**只需按一下「连接房间」**。

---

## 🔗 新增：控制链接

以前要口头/打字对两件事：**服务器地址**和**房间号**，两边任何一处填得不一样就连不上。
现在被控方创建房间后，卡片上多了两个按钮：

| 按钮 | 作用 |
|---|---|
| **🔗 复制控制链接** | 复制一条带参数的链接，主控方打开后**服务器地址与房间号都已填好** |
| **📋 只复制房间号** | 只复制 8 位房间号（对方已经知道服务器地址时用这个） |

链接长这样（两个页面在同一个目录下，所以是相对路径）：

```
RemoteMaster.html?srv=wss%3A%2F%2F你的域名&room=00420042
```

主控方打开后会发生这些事：

1. 服务器地址、房间号**自动填入**连接弹窗
2. 顶部出现一行提示：`🔗 已从控制链接读取到 服务器地址 与 房间号 xxx，确认无误后点下面的「连接房间」即可`
3. 光标直接落在「连接房间」按钮上，**按回车或点一下就开始连接**
4. 地址栏里的参数会被自动清理（刷新页面不会又弹一次，也不会把带参链接再转发出去）

### 本地调试模式也能分享

如果被控方用的是「本地调试模式」（同一浏览器两个标签页直连），复制出的链接里带的是
`local=1` 而不是服务器地址。对方打开后会自动勾上本地调试模式，同样只需按一下连接。
**这是本地验证整套流程最省事的办法。**

## 🔒 顺带修好的两个小毛病

| # | 问题 | 修复后 |
|---|---|---|
| 1 | 「复制房间号」原来用 `navigator.clipboard`，**它返回 Promise，同步 try/catch 抓不到失败**；而且 `file://` 打开时这个 API 常常直接不可用 —— 点了「复制」看似成功、其实剪贴板里什么都没有 | 加了兜底：剪贴板 API 失败时自动改用 `textarea + execCommand`；再失败就**自动选中链接框**并提示手动复制 |
| 2 | 链接属于外部输入，恶意链接可能把主控端引到任意地址 | 只接受 `ws / wss / http / https` 或纯主机名（可带端口）；`javascript:`、`data:`、`vbscript:`、`file:` 等一律忽略 |

## 🚪 房间满员 / 房间不存在：就地报错，不再"假装已连上"

一个房间只允许 **主控 + 被控两人**。以前如果房间已经满了，第三个人点「连接房间」会看到：

- 弹窗自动关掉、界面切进远程主控页
- 弹出一条绿色的「已进入房间 xxxxxxxx，等待被控方…」
- 然后**永远停在那里**，房间号、被控方离线、同步未同步，一直等下去
- 真正的原因（该房间已满）被写进了一个**已经关掉的弹窗**里，根本看不见

根因是把"WebSocket 握手成功"当成了"已经进了房间"。而服务器拒绝加入时只回一条错误、
**并不会关闭连接**，所以界面既没有报错、也没有超时。

现在改成：

| 情况 | 现在的表现 |
|---|---|
| 房间已满 | 弹窗**保持打开**，按钮下方红字提示「该房间已满（一个房间只允许主控 + 被控两人）。」 |
| 房间不存在 | 同样留在弹窗里，提示「房间不存在，请核对房间号，或让被控方重新创建。」 |
| 服务器一直不回话 | 10 秒后提示「连接超时」，不再无限卡在「连接中…」 |

配套的两个细节：

1. 只有在服务器**确认**（回了 created / joined）之后才进入远程界面、才弹「已连接房间」的提示
2. 被拒绝的那条连接会被主动收掉 —— 否则它会一直占着一条空闲连接、每 2 秒发一次保活；
   同时「连接」按钮恢复可用，**改完房间号可以直接重试，不需要刷新页面**

被拒绝后重试的路径也验证过：改房间号 → 按「连接房间」→ 正常进入（上一次的红字自动清掉）。

## ✅ 验证过的行为

- 链接生成含 `srv` / `room` 参数；房间号前导零保留（`00420042` 不会变成 `420042`）
- 主控打开链接后两个字段自动填入、提示条出现、地址栏参数被清理
- 只按一下「连接房间」即进入连接流程
- 安全过滤：`javascript:` / `data:` / `vbscript:` / `file:` 四种危险协议均被拒绝
- 复制失败时能优雅退化（不再"静默成功"）
- 房间满员 / 房间不存在时：弹窗不关、就地显示原因、不进远程界面、连接被收掉（自动化自检 35 项全通过）
- 被拒绝后直接改房间号重连成功，无需刷新页面
- 正常加入、本地调试模式（同浏览器双标签页）均照旧：服务器确认后立即进入远程界面

## 📌 已知限制

- **`file://` 打开时，链接里的路径只在本机有效**（形如 `file:///D:/.../RemoteMaster.html?...`）。
  页面会就这点给出明确提示：要发给别人请用同一份网页的**在线地址**，或者只发房间号。
- 只支持 **Chrome / Edge**（Firefox / Safari 不支持 Web Bluetooth）
- 远程控制需要**自建一台中转服务器**；被控方页面必须保持**前台运行**
