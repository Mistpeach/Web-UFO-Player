2026.9.17 波形控制器 v3.0 —— 正式版远程控制（真实服务器可用）

【本版重点：远程控制真正可用了】
v2.0 引入了远程控制的界面与本地调试，但 WebSocket 真实服务器这条路存在致命缺陷，
本版全部修复并已在自己的服务器上跑通。

—— 服务器中转（wss://）——
1. 【致命】修复业务消息无法穿过服务器：收到的中继载荷是分片信封 {c,i,n,d}，
   真正消息在 d 里，但接收侧从未拆包，导致每条业务消息都被判为 no-type 丢掉。
   表现为：房间能建、两端能互相看到在线，但主控永远"同步中"、看不到被控信息、
   也控制不了对方。现已接入分片重组，超过 8KB 的完整波形也能正确送达。
2. 主控在状态里捎带两个"只有它测得出"的值，被控端界面这才显示得出：
   · 主控↔服务器 延迟　· 时钟偏差　（端到端估算 = 本端↔服务器 + 主控↔服务器）
3. 被控解锁后主控能自动恢复：新增 resume 报文（被控 → 主控）。
   在此之前主控无法自行解除急停锁定（这是安全设计），被控点了解锁主控那边却一直灰着。

—— 同步与恢复 ——
4. 【重要】修复同步死循环：主控每收到一次 ACK 都会重新推一版状态，版本号无限空转，
   同步永远到不了"已同步"，同时以每秒几十条的速率空刷网络（实测 3 秒 93 次 → 1 次）。
5. 【重要】主控掉线超过 8 秒再回来，链路恢复后能自动继续，不再需要手动解锁或重开房间：
   · 被控侧：失联标记永不清除，同一次失联只处理一次；现已在对端消息到达时清除
   · 主控侧：失联时未把对端标记为离线，"对端回来"这件事从未被察觉，因此从不补推状态
   · 被控侧：安全停机后锁定无法自动放开，现已区分"失联临时停机"与"用户急停永久锁定"
6. 主控主动退出 / 关标签页时发送 bye 报文，被控立即停机（原来要白等约 6.5 秒心跳超时）。

—— 安全（重要）——
7. 【安全】被控急停不再依赖蓝牙健康：原先把 eng.setEnabled、ble.send、requestStop
   挤在同一个 try 里，蓝牙一断 ble.send 抛异常就导致急停信号发不出去 ——
   主控完全收不到急停，仍在正常下发命令。现已拆成各自独立的 try。
8. 区分两种锁定并在界面上说明：
   · 用户急停 → 永久锁定，只有被控方能解锁（主控无权解除）
   · 失联/蓝牙断开导致的安全停机 → 临时停机，链路恢复后自动继续
9. 被控端三处失联兜底（自己断 / 主控离开 / 心跳超时）仍统一走同一个安全停机出口。

—— 通道独立与示波器 ——
10. 【重要】A/B 通道彻底分开：引擎的 setEnabled 每次调用都会把时间原点重置到此刻，
    而同步侧对两路都照调一遍，导致"主控只调 B 通道参数，A 通道波形却从头重播"。
    现在逐通道比对，没变化的通道一律不碰引擎。
11. 主控端波形图从空白修复：卡片里缺 canvas 元素，且从未调用 scope.attach，
    所以画布对象不存在、setWave 直接返回。已补上画布、挂载与窗口缩放重绘。
12. 时间扫描线语义确定下来：
    · 换波形时从新波形开头播（不再接着旧波形扫描线的位置）
    · 取消某个通道输出时，扫描线停在起始位置（时间轴冻结）
    · 主控端勾选通道后扫描线正常前进（原来主控从不更新本地引擎，相位恒为 0）

—— 界面 ——
13. 主控页顶部去掉「连接蓝牙」按钮与"远程模式下不可用"的提示，换成「🔗 连接房间」，
    随时可重连或换房间。
14. 修复两个页面上「保持前台运行」右侧的问号点不动：既缺 #tipModal.open 样式，
    元素上又有内联 display:none 把样式压住。
15. 被控端创建房间后直接允许输出，不必先点一次「解锁」。
16. 被控端向导修复：服务器地址输入框与「测试连接 / 创建房间」按钮在流程推进后
    永久灰掉且没有退路；现已修正步骤推进与可用性判定，并加了「重新设置」退回入口。
17. 主控端 A/B 通道复选框连接成功后仍灰、点不动：初始化时被一次性置灰，
    渲染函数从不恢复；现改为每次渲染依据锁定状态重算。
18. 修掉几处状态残留：急停后卡片高亮不熄灭、退出远程后锁定标志不复位、
    被控端信息面板只显示 A 通道波形、弹窗异常被静默吞掉。

【协议与文档】
- 业务消息新增 bye（主控告别）与 resume（被控解锁），协议文档已同步。
- RemoteServer/ 下含服务器程序、部署教程（宝塔 / 命令行 / Caddy / Nginx / Docker）、
  协议文档与原理说明；服务器对业务载荷只做转发、不解析。

【环境】
- 仍然是纯静态、零依赖、零构建，全部页面都能直接双击（file://）打开。
- BLE 协议未改动，与既有固件保持兼容。
- 远程控制需要一台自己的中转服务器；没有服务器也能用两个页面里的
  「本地调试模式」（同一浏览器两个标签页直连）先跑通全部逻辑。
