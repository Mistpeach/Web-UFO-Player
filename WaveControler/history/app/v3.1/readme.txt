2026.9.18 波形控制器 v3.1 —— 一键分享控制链接 + 远程界面一屏放下

【本次重点：被控方建房后，直接甩一条链接过去就行】
1. 被控方创建房间后，房间卡片上新增两个按钮：
   · 「🔗 复制控制链接」—— 链接里带上「服务器地址 + 房间号」
   · 「📋 只复制房间号」—— 对方已经知道服务器地址时用这个
2. 主控方打开这条链接后，服务器地址与房间号**自动填好**，顶部给一行
   "已从控制链接读取到 服务器地址 与 房间号 xxx" 的说明，光标直接落在
   「连接房间」上 —— 按回车或点一下就开始连接，不需要再对账任何参数。
   地址栏里的参数会被自动清理（刷新不会又弹一次，也不会把带参链接再转发出去）。
3. 本地调试模式同样可以分享：链接里带 local=1 而不是服务器地址，对方打开后
   会自动勾上本地调试模式。这是本地验证整套远程流程最省事的办法。
4. 链接里的服务器地址属于外部输入，做了白名单过滤：只接受 ws / wss / http / https
   或纯主机名（可带端口）；javascript:、data:、vbscript:、file: 一律拒绝。

【复制为什么会失败】
5. 原来「复制房间号」用的是 navigator.clipboard，它返回 Promise，同步 try/catch
   抓不到失败；而用 file:// 打开时这个 API 常常直接不可用 —— 点了"复制"看似成功、
   剪贴板里其实什么都没有。现在加了兜底链：剪贴板 API → textarea + execCommand
   → 仍然失败就自动选中链接框并提示手动复制。

【界面：尽量一屏放下（可滚动只是兜底）】
6. 远程主控页改为响应式高度：示波器高度不再贪婪占满剩余空间，而是用
   clamp() 依据"当前可用高度 - 固定占用"实时计算，上下限 64px ~ 150px
   （手机横屏等极矮窗口下下限降到 56px）。原来每张通道卡都被撑到 699px 高，
   A/B 两路根本没法同屏。
7. 顺带定死了两条滚动底线：
   · 被控页向导与远程主控页的正文容器自己可滚（原来 body 是 100dvh + overflow:hidden，
     而里面的容器既没有 flex 也没有 overflow，整页就卡死滚不动）
   · 主控页 #cards 保留自身滚动，作为极端窗口尺寸下的兜底
   实测 1264×625 / 1350×673 / 1424×805 / 1904×985 / 500×749 等尺寸下都能一屏显示；
   只有手机横屏（约 724×265）仍需滚动，这是有意保留的兜底路径。
   注：窗口高度低于 900px 时信息面板（时钟偏差、端到端）会隐藏，以保证两张通道卡完整可见。
8. 主控页顶栏去重：原来顶栏的「远程控制中 / 房间号」与下方状态条完全重复，一屏出现两遍；
   现在顶栏只显示"我在哪个页面"，连接状态与房间号统一由状态条呈现。
9. 远程页的版本号集中到 js/sharelink.js 一处（APP_VERSION）：被控页与主控页的顶栏
   标题由它生成（不再各写一份），四个页面的 <title> 也都带上了版本号。

【连接可靠性】
10. 房间满员 / 房间不存在时不再"假装连上了"：
    以前第三人点「连接房间」会看到弹窗自动关掉、界面切进远程主控页、并且弹出一条
    绿色的"已进入房间 xxxxxxxx，等待被控方…"，然后永远停在那里 —— 真正的原因
    （该房间已满）被写进了一个已经关掉的弹窗里，根本看不见。
    根因是把"WebSocket 握手成功"当成了"已经进了房间"，而服务器拒绝加入时只回一条
    错误、并不关闭连接。现在区分 opened（握手完成）与 joined（服务器确认进了房间），
    被拒时弹窗保持打开、红字写在按钮下方、连接被主动收掉，「连接」按钮恢复可用，
    改完房间号可以直接重试，不需要刷新页面。
    同时 10 秒超时的判据也改成"是否进了房间"，服务器一直不回话时会正常报超时，
    不再无限卡在"连接中…"。
11. 服务器回收房间（长时间无活动）时，主控端会显示对应提示，不再只显示英文错误码。

【环境】
- 仍然是纯静态、零依赖、零构建，全部页面都能直接双击（file://）打开。
- BLE 协议未改动，与既有固件保持兼容。
- 远程控制需要一台自己的中转服务器；没有服务器也能用两个页面里的
  「本地调试模式」（同一浏览器两个标签页直连）先跑通全部逻辑。
