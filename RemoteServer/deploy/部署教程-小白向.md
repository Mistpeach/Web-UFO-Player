# 远程控制服务器 · 部署教程（小白向）

> 环境：**阿里云轻量应用服务器 + Ubuntu + 宝塔面板**，有一个公网 IP，实际通过**域名**访问。
> 全程只需要会：登录面板、点按钮、复制粘贴命令。
> 预计耗时 20~30 分钟，其中大部分时间是在等域名解析生效。

---

## 0. 这个服务器是干什么的

它是**远程控制的中转站**，本身不碰蓝牙、不存你的波形数据。数据流是这样的：

```
主控方的浏览器  ──wss──►  【这台服务器】  ──wss──►  被控方的浏览器  ──蓝牙──►  玩具
```

服务器只做两件事：
1. 让两个人（主控 + 被控）通过同一个「房间号」找到对方
2. 原样转发他们之间的消息（**不解析内容、不落盘**）

**几个必须先知道的结论：**

| 事项 | 说明 |
|---|---|
| 服务器**不理解**你的波形数据 | 它只看到"两个客户端在互相发 JSON"，所以协议升级不需要动服务器 |
| 服务器**不记录**你的波形 | 只记录连接日志（谁在什么时候连了、断开了），不记录消息内容 |
| **必须用 HTTPS（wss）** | 如果网页是 `https://` 打开的，浏览器会**拒绝**明文 `ws://`。必须配证书 |
| 一个房间**最多 2 人** | 主控 + 被控。将来放开多人只需改配置 |
| 房间空闲 **10 分钟**自动回收 | 最后一个消息算起 |
| **被控方网页必须一直开着** | 玩具的蓝牙由它持有。关掉页面 = 会话结束 + 安全停机 |

## 1. 准备工作清单

开始前请确认你有：

- [ ] 阿里云轻量应用服务器（Ubuntu 系统），能登录**宝塔面板**
- [ ] 一个域名，并且**能改 DNS 解析**（加一条 A 记录）
- [ ] 服务器的**公网 IP**
- [ ] 本教程的 `RemoteServer` 文件夹

> 💡 没有域名也能跑，但就只能用 `http://IP:端口` 访问，**浏览器会拦明文 ws**，实际用不了远程控制。
> 所以域名 + HTTPS 是必需的，不是可选项。

---

## 2. 第一步：放行端口

### 2.1 阿里云安全组

1. 登录阿里云控制台 → 轻量应用服务器 → 找到你的实例
2. 左侧「**安全**」→「**防火墙**」
3. 添加规则，放行这两个端口：

| 协议 | 端口 | 用途 | 建议来源 |
|---|---|---|---|
| TCP | **80** | HTTP（用于申请证书时验证域名） | 全部（0.0.0.0/0） |
| TCP | **443** | HTTPS / WSS（**这才是实际用的**） | 全部（0.0.0.0/0） |

> ⚠️ **不要**把应用端口（默认 8787）开放到公网。它只在本机被反向代理访问，不对外暴露。

### 2.2 宝塔面板的防火墙

宝塔面板 →「**安全**」→ 放行 `80` 和 `443`。

---

## 3. 第二步：域名解析

1. 到你买域名的地方（阿里云域名 / 腾讯云 / Cloudflare 都行）→ DNS 解析
2. 添加一条记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `ufo`（或你想要的前缀，比如 `remote`） | 你的服务器公网 IP |

3. 保存后，等几分钟，然后在本机命令行验证：

```bash
ping ufo.你的域名.com
```

能 ping 到你的公网 IP 就说明生效了。

> 举例：解析记录填 `ufo` + 域名 `example.com` → 以后访问地址就是 `wss://ufo.example.com`

---

## 4. 第三步：装 Node.js

宝塔面板 →「**软件商店**」→ 搜索「**Node.js 版本管理器**」→ 安装。

装好后点它 →「**安装 Node 版本**」→ 选 **LTS 版本（18 或 20 都行）**→ 安装。

装完在「命令行」里验证一下：

```bash
node -v
```

能打印出版本号（比如 `v20.11.1`）就对了。

> 本项目服务器**零第三方依赖**，不需要 `npm install`。只要求 Node 18+。

---

## 5. 第四步：上传服务器代码

1. 宝塔面板 →「**文件**」→ 进入 `/www/wwwroot/`
2. 新建一个文件夹，名字比如 `ufo-remote`
3. 进入这个文件夹 → 点「**上传**」→ 把 `RemoteServer` 文件夹里的**全部文件**传上去

传完后目录应该长这样：

```
/www/wwwroot/ufo-remote/
├── server.js
├── config.example.json
├── package.json
├── ecosystem.config.js
├── logs/
└── deploy/
```

> 如果宝塔的文件管理器不支持直接传文件夹，就自己新建 `logs` 目录，再把各个文件分别传上去。

---

## 6. 第五步：改配置

1. 在 `/www/wwwroot/ufo-remote/` 里，把 `config.example.json` **复制一份**，重命名为 **`config.json`**
2. 双击 `config.json` 编辑，只需要改这几项（其余保持默认）：

```json
{
  "server": {
    "port": 8787,
    "trustProxy": true
  },
  "log": {
    "level": "info",
    "ipMode": "full",
    "retainDays": 14
  }
}
```

| 字段 | 说明 |
|---|---|
| `server.port` | 应用监听端口，**保持 8787 即可**。它只监听在本机，不对外 |
| `server.trustProxy` | **必须为 `true`**，否则日志里记录的会是反向代理的 IP 而不是真实客户端 IP |
| `log.ipMode` | `full` 记完整 IP（便于追溯滥用）；`masked` 会把 IP 最后一段变成 `x` |
| `log.level` | `info` 够用。排查问题时可以临时改 `debug` |

> `config.json` 里的字段**可以只写你想改的那几个**，其余自动用默认值。

---

## 7. 第六步：先手动跑一次，确认能起来

宝塔面板 →「**终端**」（或在阿里云控制台点「远程连接」）：

```bash
cd /www/wwwroot/ufo-remote
node server.js
```

**成功的话会看到类似这样的输出：**

```
[info] server-started  port=8787  path=/ws  version=1.0.0
[info] log-dir  dir=/www/wwwroot/ufo-remote/logs
```

**另开一个终端窗口**，验证健康检查：

```bash
curl http://127.0.0.1:8787/health
```

应该返回一段 JSON（包含在线房间数、连接数、运行时长、版本）。看到 JSON 就说明服务正常。

然后按 `Ctrl + C` 停掉（接下来要交给守护进程管理）。

### 如果起不来

| 报错 | 原因与解决 |
|---|---|
| `EADDRINUSE` | 8787 端口被占用。换一个端口（改 `config.json` 的 `port`），或先杀掉占用进程 |
| `Cannot find module './config.json'` | 没关系，配置文件可选。真报这个错误说明路径不对，确认在 `ufo-remote` 目录下执行 |
| `node: command not found` | Node 没装好，回到第三步 |

## 8. 第七步：让它一直运行（守护进程）

**方式 A：宝塔的 Node 项目管理器（推荐，小白友好）**

1. 宝塔 →「**网站**」→「**Node 项目**」→「添加 Node 项目」
2. 填写：
   - **项目名称**：`ufo-remote`
   - **项目目录**：`/www/wwwroot/ufo-remote`
   - **启动文件**：`server.js`
   - **Node 版本**：选你装的那个
   - **端口**：`8787`
3. 保存 → 启动
4. 点「**开机自启**」打开

**方式 B：pm2（更灵活）**

```bash
cd /www/wwwroot/ufo-remote
npm i -g pm2
pm2 start ecosystem.config.js
pm2 save
pm2 startup
```

> `pm2 startup` 会打印一行命令，**把那行命令复制出来再执行一次**，否则重启服务器后不会自动启动。

之后常用命令：

```bash
pm2 status          # 看状态
pm2 logs ufo-remote # 看日志
pm2 restart ufo-remote
pm2 stop ufo-remote
```

## 9. 第八步：配反向代理 + HTTPS（关键一步）

**为什么必须做这一步**：用户是通过 `https://` 打开网页的，浏览器会**拦截明文 `ws://`**。
所以需要一层能处理证书的反向代理，把 `wss://你的域名` 转发到本机的 `127.0.0.1:8787`。

### 方式 A：宝塔反向代理（小白向）

1. 宝塔 →「**网站**」→「**添加站点**」
   - **域名**：`ufo.你的域名.com`（就是第 3 步解析的那个）
   - **根目录**：随便建一个空目录即可
   - **PHP 版本**：纯静态
2. 站点建好后，点「**设置**」→「**SSL**」
   - 选「**Let's Encrypt**」→ 勾选域名 → 申请
   - 申请成功后打开「**强制 HTTPS**」
3. 回到「设置」→「**反向代理**」→「添加反向代理」
   - **代理名称**：`ufo-remote`
   - **目标 URL**：`http://127.0.0.1:8787`
   - **发送域名**：`$host`
   - 保存

**⚠️ 关键：必须开启 WebSocket 支持。** 宝塔的反向代理有时不带 Upgrade 头，会导致连接失败。
保存后点该代理的「**配置文件**」，确认里面有这两行（没有就手动加上）：

```nginx
proxy_set_header Upgrade $http_upgrade;
proxy_set_header Connection "upgrade";
```

改完**重载 Nginx**。

### 方式 B：Caddy（自动 HTTPS，配置最简单）

如果不想手工折腾证书，可以直接用 Caddy。参考 `deploy/Caddyfile`：

```
ufo.你的域名.com {
    reverse_proxy 127.0.0.1:8787
}
```

Caddy 会**自动申请并续期证书**，也自动处理 WebSocket 升级。装法：

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update && sudo apt install -y caddy
```

把上面的 Caddyfile 内容写到 `/etc/caddy/Caddyfile`，然后：

```bash
sudo systemctl reload caddy
```

> 用了 Caddy 就**不要**再开宝塔的反向代理，两者会抢 443 端口。

## 10. 第九步：验证

按顺序验证，每一步都要过：

### ① 健康检查（本机）

```bash
curl http://127.0.0.1:8787/health
```

→ 返回 JSON ✅

### ② 健康检查（外网，走域名 + HTTPS）

浏览器打开：

```
https://ufo.你的域名.com/health
```

→ 返回同样的 JSON ✅

> 如果这里打不开，说明反向代理或证书没配好，**先解决这一步再往下**。

### ③ WebSocket 握手

浏览器按 F12 → Console，粘贴这段（把域名换成你的）：

```js
const ws = new WebSocket('wss://ufo.你的域名.com/ws');
ws.onopen = () => { console.log('✅ WS 已连接'); ws.send(JSON.stringify({t:'create'})); };
ws.onmessage = e => console.log('收到:', e.data);
ws.onerror = () => console.log('❌ WS 连接失败');
ws.onclose = e => console.log('关闭:', e.code, e.reason);
```

期望看到：

```
✅ WS 已连接
收到: {"t":"created","room":"12345678","role":"slave",...}
```

拿到 8 位房间号就说明**服务器完全可用**了。

### ④ 用真实页面跑通

1. 打开 `RemoteSlave.html` → 连蓝牙 → 填 `wss://ufo.你的域名.com` → 创建房间
2. 另一台设备打开 `RemoteMaster.html` → 填同一个地址 + 房间号 → 连接
3. 主控选波形、调强度、开输出 → 被控方的设备应该动起来

## 11. 日常维护

| 做什么 | 怎么做 |
|---|---|
| 看运行状态 | `curl http://127.0.0.1:8787/health` 或浏览器打开 `/health` |
| 看日志 | 宝塔「文件」→ `/www/wwwroot/ufo-remote/logs/`，或 `pm2 logs ufo-remote` |
| 日志在哪 | `logs/main/` 是主日志，`logs/limits/` 是限流记录；**按天轮转，保留 14 天自动清理** |
| 改配置 | 改 `config.json` 后重启服务（`pm2 restart ufo-remote` 或宝塔里点重启） |
| 升级代码 | 覆盖 `server.js` 等文件后重启服务。**`config.json` 和 `logs/` 不要覆盖** |
| 看谁连过 | 搜日志里的 `ws-open` / `ws-close` 事件，含 IP、时间、断开原因 |

> ⚠️ **修改代码后必须重启**，服务器不会热加载。

## 12. 常见问题

**Q：`https://域名/health` 打不开，但本机 `curl 127.0.0.1:8787/health` 正常？**
A：反向代理或证书没配好。检查：域名解析是否生效、宝塔站点是否绑定了这个域名、SSL 是否申请成功、反代目标是否是 `http://127.0.0.1:8787`。

**Q：页面提示 WS 连接失败，F12 里看到 403 或 404？**
A：多半是反向代理漏了 WebSocket 支持。确认 Nginx 配置里有 `proxy_set_header Upgrade $http_upgrade;` 和 `proxy_set_header Connection "upgrade";`，然后重载 Nginx。

**Q：浏览器 Console 报 "Mixed Content" 或 "insecure WebSocket"？**
A：页面是 `https://`，但你填的是 `ws://`。必须改成 `wss://`。

**Q：日志里的 IP 全是 `127.0.0.1`？**
A：`config.json` 里的 `server.trustProxy` 没设成 `true`。

**Q：证书申请失败？**
A：常见原因：域名没解析到本机、80 端口没放行、或者 80 端口被别的服务占用。先在浏览器打开 `http://你的域名` 看能不能访问。

**Q：服务器重启后服务没起来？**
A：pm2 需要执行过 `pm2 save` 和 `pm2 startup`（并把 startup 打印的那行命令也执行一次）；宝塔的 Node 项目需要打开「开机自启」。

**Q：能同时开多个房间吗？**
A：可以。一个房间 2 人，房间之间互不影响，上限由 `server.maxConnections` 控制（默认 5000 个连接）。

**Q：我不想让别人乱建房，怎么限制？**
A：`config.json` 的 `rateLimit` 里 `enabled` 设为 `true`（默认已开），每个 IP 每分钟最多建房/加入 10 次。日志里会记录被限流的 IP。

## 13. 安全建议

服务器是公开的，虽然它不存你的数据，但仍建议：

1. **一定要用 HTTPS**（`wss://`）—— 否则消息在网络上明文可见
2. **不要把 8787 端口开放到公网**，只让反向代理本机访问
3. **房间号不要发到公开频道** —— 拿到房间号的人就能加入房间。建议私聊发给对方
4. **日志里默认记完整 IP**。如果你在意隐私，把 `log.ipMode` 改成 `masked`
5. 定期看日志有没有异常的大量连接（可能是被扫描或滥用），必要时用 `rateLimit` 收紧
6. **被控方的急停永远最高优先级**，主控无法解除 —— 这是设计上的安全底线，不要改
