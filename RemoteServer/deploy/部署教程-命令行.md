# 远程控制服务器 · 部署教程（命令行版）

> 面向不用宝塔面板的用户。以 **Ubuntu 22.04 / 24.04** 为例。
> 如果你更习惯图形界面，看 `部署教程-小白向.md`（阿里云轻量 ECS + 宝塔面板）。
>
> 全程只需复制粘贴。预计 15 分钟。

---

## 0. 你会得到什么

```
你的域名:443 ──(Caddy 自动 HTTPS)──► 127.0.0.1:8787 ──(Node)──► 房间中继
```

Caddy 负责申请和续期证书、并把 `wss://` 转发到本机的 Node 服务。
Node 服务只监听本机，不对外暴露。

**前置条件：**
- 一台有公网 IP 的 Ubuntu 服务器
- 一个域名，能改 DNS 解析
- 能 SSH 登录（或云厂商的网页终端）

---

## 1. 域名解析

在你买域名的地方加一条 A 记录：

| 类型 | 主机记录 | 记录值 |
|---|---|---|
| A | `ufo`（或任意前缀） | 你的服务器公网 IP |

等几分钟，然后验证：

```bash
dig +short ufo.你的域名.com     # 应输出你的公网 IP
# 或者
ping -c 3 ufo.你的域名.com
```

> 后面所有出现 `ufo.你的域名.com` 的地方都换成你自己的。

---

## 2. 放行端口

```bash
# Ubuntu 自带的 ufw（如果启用了）
sudo ufw allow 80/tcp
sudo ufw allow 443/tcp
sudo ufw reload
sudo ufw status
```

**同时别忘了云厂商的安全组/防火墙**（阿里云、腾讯云、AWS 等都要单独放行 80 和 443）。
这一步漏了的话，后面证书申请会失败。

## 3. 安装 Node.js 18+

用 NodeSource 官方源（比 apt 自带的版本新）：

```bash
curl -fsSL https://deb.nodesource.com/setup_20.x | sudo -E bash -
sudo apt-get install -y nodejs
node -v      # 应输出 v20.x.x
```

> 也可以用 nvm 管理多版本：
> ```bash
> curl -o- https://raw.githubusercontent.com/nvm-sh/nvm/v0.39.7/install.sh | bash
> source ~/.bashrc
> nvm install 20 && nvm use 20
> ```

**本项目零第三方依赖，不需要 `npm install`。**

## 4. 上传代码

```bash
sudo mkdir -p /opt/ufo-remote
sudo chown -R $USER:$USER /opt/ufo-remote
```

把 `RemoteServer/` 里的文件传上去。两种方式：

**方式 A：从本地上传（在你自己的电脑上执行）**

```bash
scp -r RemoteServer/* 你的用户名@服务器IP:/opt/ufo-remote/
```

**方式 B：在服务器上直接从 Git 仓库拉（只取需要的目录）**

```bash
cd /tmp
git clone --depth 1 https://github.com/Mistpeach/Web-UFO-Player.git
cp -r Web-UFO-Player/RemoteServer/* /opt/ufo-remote/
```

验证：

```bash
cd /opt/ufo-remote
ls -la
# 应该看到 server.js / config.example.json / package.json / deploy/ 等
```

## 5. 配置

```bash
cd /opt/ufo-remote
cp config.example.json config.json
nano config.json      # 或 vim / 或直接用 scp 改本地文件再传
```

**最小改动**（其余保持默认）：

```json
{
  "server": {
    "port": 8787,
    "trustProxy": true
  },
  "log": {
    "ipMode": "full",
    "retainDays": 14
  }
}
```

| 字段 | 为什么这么填 |
|---|---|
| `port` | 保持 8787。它只监听本机，由 Caddy 转发 |
| `trustProxy` | **必须 `true`**，否则日志里记的是 127.0.0.1 而不是真实客户端 IP |
| `ipMode` | `full` 记完整 IP（便于追溯）；在意隐私就改 `masked` |

## 6. 先手动跑一次

```bash
cd /opt/ufo-remote
node server.js
```

**期望输出：**

```
[info] server-started  port=8787  path=/ws  version=1.0.0
```

**另开一个终端**验证：

```bash
curl -s http://127.0.0.1:8787/health | head -c 400
```

应该返回 JSON。看到就按 `Ctrl+C` 停掉，接下来交给 systemd 管理。

**如果起不来：**

| 报错 | 解决 |
|---|---|
| `EADDRINUSE` | 8787 被占用。改 `config.json` 的 `port`，或 `sudo lsof -i :8787` 找出占用进程 |
| `node: command not found` | Node 没装好，回第 3 步 |

## 7. 用 systemd 守护（开机自启）

```bash
sudo cp /opt/ufo-remote/systemd/ufo-remote.service /etc/systemd/system/
sudo nano /etc/systemd/system/ufo-remote.service
```

确认里面的路径和用户名与你的实际一致（默认是 `/opt/ufo-remote` 和 `www-data`）：

```ini
[Unit]
Description=UFO Assistant Remote Relay
After=network.target

[Service]
Type=simple
WorkingDirectory=/opt/ufo-remote
ExecStart=/usr/bin/node /opt/ufo-remote/server.js
Restart=always
RestartSec=3
StandardOutput=journal
StandardError=journal
SyslogIdentifier=ufo-remote

# 安全加固：只允许写日志目录
NoNewPrivileges=true
PrivateTmp=true
ProtectSystem=strict
ReadWritePaths=/opt/ufo-remote/logs
ProtectHome=true

[Install]
WantedBy=multi-user.target
```

> **注意**：`ProtectSystem=strict` 会让整个文件系统只读，只有 `ReadWritePaths` 里列出的目录可写。
> 所以 `logs` 目录的属主必须是运行用户，且 `config.json` 需要可读：
> ```bash
> sudo chown -R www-data:www-data /opt/ufo-remote/logs
> sudo chmod 644 /opt/ufo-remote/config.json
> ```
> 如果你觉得这套加固麻烦，可以先把 `ProtectSystem` 那几行注释掉，跑通之后再开。

启用：

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now ufo-remote
systemctl status ufo-remote
```

**看日志：**

```bash
journalctl -u ufo-remote -f              # systemd 捕获的标准输出
tail -f /opt/ufo-remote/logs/main/*.log  # 服务器自己写的日志文件
```

**常用命令：**

```bash
sudo systemctl restart ufo-remote
sudo systemctl stop ufo-remote
sudo systemctl disable ufo-remote
```

## 8. 用 Caddy 做 HTTPS 反代（自动证书）

**为什么必须做**：用户的网页是 `https://`，浏览器会**拦截明文 `ws://`**。
Caddy 会自动申请 Let's Encrypt 证书、自动续期、自动处理 WebSocket 升级。

### 安装

```bash
sudo apt install -y debian-keyring debian-archive-keyring apt-transport-https curl
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/gpg.key' | sudo gpg --dearmor -o /usr/share/keyrings/caddy-stable-archive-keyring.gpg
curl -1sLf 'https://dl.cloudsmith.io/public/caddy/stable/debian.deb.txt' | sudo tee /etc/apt/sources.list.d/caddy-stable.list
sudo apt update
sudo apt install -y caddy
```

### 配置

```bash
sudo cp /opt/ufo-remote/deploy/Caddyfile /etc/caddy/Caddyfile
sudo nano /etc/caddy/Caddyfile
```

把里面的域名改成你自己的：

```
ufo.你的域名.com {
    encode gzip
    reverse_proxy 127.0.0.1:8787
    log {
        output file /var/log/caddy/ufo-remote.log
        format json
    }
}
```

> **Caddy 不需要你手工写 `Upgrade` / `Connection` 头** —— 它识别到反向代理会自动处理 WebSocket。
> 这是它比 Nginx 省事的地方。

### 启动

```bash
sudo mkdir -p /var/log/caddy
sudo chown -R caddy:caddy /var/log/caddy
sudo systemctl reload caddy
sudo systemctl status caddy
```

首次访问时 Caddy 会自动申请证书（约 10~30 秒）。看日志确认：

```bash
journalctl -u caddy -f
# 看到 "certificate obtained successfully" 就对了
```

## 9. 验证清单

按顺序走，每一步都要过：

### ① 本机健康检查

```bash
curl -s http://127.0.0.1:8787/health
```
→ 返回 JSON ✅

### ② 外网健康检查（走域名 + HTTPS）

```bash
curl -s https://ufo.你的域名.com/health
```
→ 返回同样的 JSON ✅

> 打不开就说明 DNS、安全组、证书或反代有问题。**先解决这一步再往下。**

### ③ WebSocket 握手

```bash
# 装个 wscat（临时用）
sudo npm i -g wscat
wscat -c wss://ufo.你的域名.com/ws
```

连上后输入：

```json
{"t":"create"}
```

应立刻返回：

```json
{"t":"created","room":"48192037","role":"slave","peerId":"...","members":1,"maxMembers":2,"s":...}
```

拿到 8 位房间号 → **服务器完全可用**。

### ④ 双端实测

```bash
# 终端 A
wscat -c wss://ufo.你的域名.com/ws
> {"t":"create"}            # 记下房间号
```

```bash
# 终端 B
wscat -c wss://ufo.你的域名.com/ws
> {"t":"join","room":"48192037"}
```

终端 A 应收到 `{"t":"peer","event":"joined",...}`。
然后在 B 里发：

```json
{"t":"relay","payload":{"hello":"world"}}
```

A 应收到 `{"t":"relay","from":"...","payload":{"hello":"world"},"s":...}`。

**测延迟**：B 发 `{"t":"ping","c":12345}`，应收到 `{"t":"pong","c":12345,"s":...}`。

### ⑤ 用真实页面跑通

1. 打开 `RemoteSlave.html` → 连蓝牙 → 填 `wss://ufo.你的域名.com` → 创建房间
2. 另一台设备打开 `RemoteMaster.html` → 填同一地址 + 房间号 → 连接
3. 主控选波形、调强度、开输出 → 被控方的设备动起来

## 10. 日常维护

```bash
# 状态
systemctl status ufo-remote
curl -s https://ufo.你的域名.com/health | python3 -m json.tool

# 日志
tail -f /opt/ufo-remote/logs/main/*.log      # 主日志
tail -f /opt/ufo-remote/logs/error.log       # 错误日志
journalctl -u ufo-remote --since "1 hour ago"

# 改配置后重启
sudo systemctl restart ufo-remote

# 升级代码
cd /opt/ufo-remote
sudo cp server.js server.js.bak              # 备份（可选）
# 覆盖新的 server.js / config.example.json（不要覆盖 config.json 和 logs/）
sudo systemctl restart ufo-remote

# 看谁连过
grep -h 'ws-open\|ws-close' /opt/ufo-remote/logs/main/*.log | tail -50
```

> ⚠️ **改代码后必须重启服务**，服务器不热加载。

## 11. 常见问题

**Q：`https://域名/health` 打不开，但本机 `curl 127.0.0.1:8787/health` 正常**

检查顺序：
1. `dig +short ufo.你的域名.com` 是否指向你的公网 IP
2. 云厂商安全组是否放行 80 和 443
3. `systemctl status caddy` 是否正常
4. `journalctl -u caddy -n 50` 有没有证书申请失败
5. 80 端口是否被别的服务（比如 Nginx）占用 —— `sudo lsof -i :80`

**Q：wscat 连不上，报 403 / 404**

- 403：多半是反代漏了 WebSocket 的 `Upgrade` 头。Caddy 会自动处理；如果你用的是 Nginx，看 `deploy/nginx.conf.example` 里的 `proxy_set_header` 两行
- 404：路径不对。确认连的是 `/ws`（`wss://域名/ws`），且 `config.json` 的 `server.path` 没改过

**Q：证书申请失败**

常见原因：域名没解析到本机、80 端口被占用、云防火墙没放行。
先用浏览器打开 `http://你的域名` 看能不能访问（能访问说明 80 通了）。

Caddy 申请失败时可以在日志里看到具体原因：
```bash
journalctl -u caddy -n 100 | grep -i 'acme\|challenge\|error'
```

**Q：日志里 IP 全是 `127.0.0.1`**

`config.json` 的 `server.trustProxy` 没设成 `true`。

**Q：`ProtectSystem=strict` 之后服务起不来 / 写不了日志**

```bash
sudo chown -R www-data:www-data /opt/ufo-remote/logs
sudo chmod 644 /opt/ufo-remote/config.json
sudo systemctl restart ufo-remote
```
还是不行就先把 systemd 文件里 `ProtectSystem` 那几行注释掉，跑通再开。

**Q：服务器重启后服务没起来**

`sudo systemctl is-enabled ufo-remote` 应该输出 `enabled`。不是的话 `sudo systemctl enable ufo-remote`。
如果是用 pm2 部署的，需要执行过 `pm2 save` 和 `pm2 startup`（并把 startup 打印的那行命令也执行一次）。

**Q：想换端口**

改 `config.json` 的 `server.port`，同时改 Caddyfile 里的 `reverse_proxy 127.0.0.1:<新端口>`，然后两个服务都重启。

**Q：能跑多少个房间？**

见 `PRINCIPLE.md` 第 9 节。结论：CPU 几乎不是瓶颈，**带宽才是**。
按每个房间约 240 B/s 估算，3 Mbps 出口大约能支撑 1500 个同时在线房间。
个人使用远远够用。

## 12. 用 Docker 部署（可选）

见 `docker/` 目录：

```bash
cd /opt/ufo-remote/docker
docker compose up -d
docker compose logs -f
```

容器部署时注意：**`config.json` 和 `logs/` 要用卷挂载出去**，否则重建容器会丢日志。
Caddy 仍然建议装在宿主机上（它要抢 80/443 并管理证书）。

## 13. 安全建议

1. **一定用 HTTPS**（`wss://`）—— 否则消息在网络上明文可见
2. **不要开放 8787 到公网**，只让反代本机访问
3. **房间号私聊发送** —— 拿到房间号就能加入房间。不要发到公开频道
4. 在意隐私就把 `log.ipMode` 改成 `masked`
5. 定期看日志有没有异常的大量连接（可能被扫描或滥用），必要时收紧 `rateLimit`
6. **被控方的急停永远最高优先，主控无法解除** —— 这是设计上的安全底线，不要改
